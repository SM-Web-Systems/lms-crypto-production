## Implemented release boundaries

The manual workflow requires an explicitly prepared checkout at the workflow's exact `github.sha`. It has no arbitrary checkout default, Git pull, automatic checkout or push-to-main deployment trigger. Trusted inline bootstrap verifies physical root, repository, full SHA, clean Git status and actual executable-file blobs before running checkout code. Python wrappers use isolated imports. Do not update a checkout while cron still executes its mutable scripts.

Required non-secret configuration is `DEPLOY_DIR`, `DEPLOY_REPOSITORY`, `DEPLOY_SHA` (workflow maps the approved SHA), `DEPLOY_PROJECT`, `DEPLOY_API_CONTAINER`, `DEPLOY_WEB_CONTAINER`, `DEPLOY_DB_VOLUME`, and `DEPLOY_BACKUP_DIR`. Execution additionally requires `DEPLOY_BASE_URL`, a private independently reviewed `DEPLOY_RECOVERY_POLICY`, and literal `DEPLOY_EXECUTE=1`. Workflow `execute` defaults to false. Missing or mismatched configuration refuses execution. Never set values merely to silence a refusal.

Preflight matches desired Compose configuration, actual project/services/containers/images, data mount and volume metadata, database path and checkout. It refuses unsupported paths/configuration and requires actual existing application tables. The source is read through SQLite's read-only consistent reader, including active WAL; it is never initialized. Mandatory online backup checks available disk, SQLite integrity, expected tables, schema/financial/FK evidence, completed standalone snapshot and SHA256. Unique private backup/evidence artifacts are retained. Windows tests cannot prove Linux owner/UID/permissions behavior.

The recovery executor preserves old image IDs under unique verified tags and stores private immutable manifests before atomically publishing a pointer. Pre-publication failures preserve the prior pointer; an I/O failure after pointer replacement, including directory sync failure, needs owner inspection of the complete pointer/manifests. No image pruning, automatic DB restore, webhook replay or history deletion occurs. External prune jobs and manual deletions still require an explicit retention policy.

Compatibility requires a separately reviewed exact policy binding repository/project/database, source and target SHA, old immutable image IDs, resolved Compose digest, schema/user_version, full payments/webhook history digest and FK evidence. `review_reference` identifies independent review; it is not a signature or an automatic approval. No production policy is supplied. See `AUTH-13-rollback-safety-review.md` for the full policy contract. The historical unlabelled/missing old images and the `6763f4e` to AUTH-13 migration have **no established safe automated rollback policy**. They remain NO-GO for this executor until the owner establishes a separately reviewed recovery procedure. Do not relabel historical images to fabricate provenance.

The executor revalidates context before and after build, pins built immutable image IDs with approved OCI revision, and uses Compose without build or pull during replacement. It stops and verifies the application writer before the final pre-replacement database snapshot. Changed schema, payment/webhook state or FK evidence refuses compatible recovery. On an uncertain failure, known validated services are stopped when possible for owner reconciliation/forward repair. Unknown runtime context or a Docker stop failure returns nonzero but cannot prove services stopped; the owner must inspect actual state before acting. Even verified image recovery leaves the deployment result failed. Other database writers are unsupported; owner-confirmed sole-writer/quiesced-ingress conditions are mandatory.

Image/container identity, Docker health, API `buildSha`, SQLite readiness, unauthenticated protected-route rejection and frontend HTML availability are checked. Success evidence records requested, checked-out, built, health and deployed SHA stages. A completed release may no longer be eligible for automatic rollback after legitimate financial activity. Recorded Compose overlays are deliberately explicit; a later deployment refuses an unreconciled overlay context instead of silently accepting it.

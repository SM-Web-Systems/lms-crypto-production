### Phase 1: RED tests — prove the binding gaps exist

All tests in new file: `src/__tests__/reward-paystack-binding.test.ts`

#### T01: Currency mismatch — XLM reward rejects fiat Paystack payment
- **File**: `reward-paystack-binding.test.ts`
- **Setup**: Create user, cohort, draft reward (XLM). Mock `verifyTransaction` to return `{status:'success', amount:1000, currency:'USD', customer:{email:'user@test.com'}, ...}`
- **Action**: `fundRewardAsync(rewardId, userId, {type:'paystack', reference:'ref_1'}, idemKey)`
- **Expected (RED on current code)**: Should throw `FUNDING_CURRENCY_MISMATCH` (402)
- **Current behavior**: Returns 200 (funded) — no currency check
- **Requirement link**: Acceptance criterion 6 (XLM + fiat = fail closed)

#### T02: Amount mismatch — wrong payment amount rejected
- **File**: `reward-paystack-binding.test.ts`
- **Setup**: Create user, cohort, draft reward (amount 10000000 stroops = 1 XLM). Mock verifyTransaction with `{status:'success', amount:500, currency:'USD', ...}` (amount doesn't match)
- **Action**: `fundRewardAsync(...)`
- **Expected (RED)**: Should throw `FUNDING_AMOUNT_MISMATCH` (402) — or more precisely, FUNDING_CURRENCY_MISMATCH first since XLM≠USD
- **Note**: This test proves amount binding exists in the code path, even though the currency gate fires first for XLM. When USD rewards exist, this test becomes the primary gate.
- **Requirement link**: Acceptance criterion 1

#### T03: Ownership mismatch — different payer rejected
- **File**: `reward-paystack-binding.test.ts`
- **Setup**: Create two users (funder, imposter). Mock verifyTransaction with imposter's email as customer.email. Fund as funder.
- **Action**: `fundRewardAsync(rewardId, funderId, {type:'paystack', reference:'ref_2'}, idemKey)`
- **Expected (RED)**: Should throw `FUNDING_OWNERSHIP_MISMATCH` (403) — or FUNDING_CURRENCY_MISMATCH first for XLM
- **Note**: Like T02, this proves ownership binding exists. Will become primary gate when currency matches.
- **Requirement link**: Acceptance criterion 3

#### I03: Add PaystackBindingContext and enhance verifyPaystack()
- **File**: `src/services/rewards/rewardFundingVerifier.ts`
- **Changes**:
  1. Add `PaystackBindingContext` interface
  2. Change `verifyPaystack(source)` → `verifyPaystack(source, context)`
  3. After status check, add: currency settlement check (fail closed for XLM→fiat)
  4. After currency check: amount binding (if currencies match)
  5. After amount check: ownership binding (compare customer email to actor email via DB)
- **Key**: Currency check fires FIRST. For XLM rewards, this rejects before amount/ownership.

#### I04: Pass binding context through verifyFundingSourceAsync

- **Caller change**: `rewardService.ts` passes the context from the already-fetched reward row
